# 222. 完全二叉树的节点个数

[https://leetcode.cn/problems/count-complete-tree-nodes/description/](https://leetcode.cn/problems/count-complete-tree-nodes/description/)

## **方法一**

定义一个全成员变量记录节点个数，然后对树进行遍历（前中后层次遍历都行）就行，代码如下：

```java
class Solution {
    int sum = 0;
    public int countNodes(TreeNode root) {
        orderCount(root); 
        return sum;
    }

    public void orderCount(TreeNode root) {
        if(root == null){
            return;
        }

        sum++;
        orderCount(root.left);
        orderCount(root.right);
    }
}
```

## **方法二**

递归，先求每个节点的左子树的节点数量，再求右子树的节点数量，最后取总和再加一 （加1是因为算上当前中间节点）就是目前节点为根节点的节点数量。代码如下：

```java
class Solution {
    public int countNodes(TreeNode root) {
        return orderCount(root);
    }

    public int orderCount(TreeNode root) {
        if(root == null){
            return 0;
        }
        int leftCount = orderCount(root.left);
        int rightCount = orderCount(root.right);
        return leftCount + rightCount + 1;
    }
}
```

方法一和方法二对于每个节点都要遍历一遍，所以时间复杂度为O(n)。

## **方法三**

利用完全二叉树的性质来优化节点数量的计算。在完全二叉树中，要么根节点是满二叉树，要么根节点的每个子节点都是一个满二叉树，以此类推，如下图：

![image.png](222%20%E5%AE%8C%E5%85%A8%E4%BA%8C%E5%8F%89%E6%A0%91%E7%9A%84%E8%8A%82%E7%82%B9%E4%B8%AA%E6%95%B0/image.png)

所以遍历到一个节点的时候，如果该节点及其子树是满二叉树的话，那么直接运用公式计算该满二叉树的节点个数就OK；如果不是，那就继续往里面遍历，反正总会遇到的。那么问题来了，怎么判断该节点是不是满二叉树呢？其实在完全二叉树中，如果递归向左遍历的深度等于递归向右遍历的深度，那说明就是满二叉树。如下图：

![image.png](222%20%E5%AE%8C%E5%85%A8%E4%BA%8C%E5%8F%89%E6%A0%91%E7%9A%84%E8%8A%82%E7%82%B9%E4%B8%AA%E6%95%B0/image%201.png)

由此可以写出如下的代码：

```
class Solution {
    public int countNodes(TreeNode root) {
        if(root == null){
            return 0;
        }
        
        // 开始满二叉树的判断逻辑
        TreeNode leftNode = root.left;
        TreeNode rightNode = root.right;
        int leftDepth = 0;
        int rightDepth = 0;
        // 不断向左遍历计算深度
        while(leftNode != null){
            leftDepth++;
            leftNode = leftNode.left;
        }
				// 不断向右遍历计算深度
        while(rightNode != null){
            rightDepth++;
            rightNode = rightNode.right;
        }
				// 判断该节点组成的子树是不是满二叉树
        if(leftDepth == rightDepth){
			      //是的话直接利用满二叉树的节点数量性质来返回节点的个数，即2^(h+1) - 1
            return (int)Math.pow(2.0, leftDepth + 1) - 1;
        }

				// 否则往下递归，计算左子树和右子树的节点数，再加上根节点。
				// 同时继续寻找符合满二叉树条件的节点
        return countNodes(root.left) + countNodes(root.right) + 1;
    }
}
```

时间复杂度为O(lgn * lgn)。为什么？设树的总高度为 h，节点数为 n。完全二叉树的节点数 n 和高度 h 的关系大约是 n ≈ 2^h，即h = lgn。先看单次操作的代价，**计算 leftDepth和rightDepth**：从根节点一直向左和右走，直到 null，每次循环访问一个节点，时间复杂度为 O(h)，因此单次操作总代价为O(h)。

接下来看整体递归的深度，这里有一个隐藏的性质： **每次递归时，至少有一边的子树（左或右）会被处理为满二叉树，不再递归。**因此在完全二叉树中，从根节点开始，沿着左右深度不同的路径递归，最多递归 O(h) 次。因为每次递归都会解决一个子树的问题，而树的高度是 h。

综上，总的时间复杂度为：O(h) × O(h) = O(h²)，n ≈ 2^h，h ≈ log₂(n)，所以：O((log n)²)。

以上也解释了为什么不是O(n * lgn)？因为当判断出某棵子树是满二叉树时，直接使用公式计算该子树节点数量，避免了对该子树中所有节点的遍历。这也是**这个方法最大的优点：不用遍历所有的节点。**
