# 142.环形链表II

[https://leetcode.cn/problems/linked-list-cycle-ii/description/](https://leetcode.cn/problems/linked-list-cycle-ii/description/)

本题主要是判断一个链表是否会有环，如果有的话，需要返回环的入口。

## 方法一

用一个指针遍历链表，每遍历一个节点就把这个节点用哈希表记录。如果指针遇到`null` ，说明链表无环；如果指针遇到已经加入过哈希表的节点，那么说明链表有环，且这个节点就是进入的环的入口。代码如下：

```java
public class Solution {
    public ListNode detectCycle(ListNode head) {
        ListNode pos = head;
        Set<ListNode> visited = new HashSet<ListNode>();
        while (pos != null) {
            if (visited.contains(pos)) {
                return pos;
            } else {
                visited.add(pos);
            }
            pos = pos.next;
        }
        return null;
    }
}
```

但是这种方法时间复杂度为O(n)，下面介绍一个时间复杂度为O(1)的解法。

## 方法二

方法二比较复杂，需要一定的数学推导。首先设两个节点`slowNode`和`fastNode`，同时从头结点处开始遍历链表，不同点在于`slowNode`每次走一个节点，而`fastNode`每次走两个节点。因此如果没有环的话，`fastNode`肯定先到达链表末尾，那么用`fastNode`及其下一个节点与`null`进行判断就可以知道是否有环，我们这里只讨论有环的情况。

如果有环的话，那么`fastNode`肯定先进入环中，这时`fastNode`就像一只猎物一样不停地在环中旋转，伺机等待着`slowNode` 调入到环的陷阱中。当`slowNode`进入环之后，`fastNode` 可能已经在环中转了很多圈，也可能只有一圈，但不管怎样，一旦`slowNode`进入环，`fastNode` 此时开始猎杀时刻，也就是去追`slowNode`，直到追上为止。如下图所示为追上那一刻的示意图，可以得出`slowNode`走的距离为x+y，`fastNode` 走的距离为x+n(y+z)+y，`fastNode` 每次比`slowNode` 多走一步，因此`fastNode` 走的距离是`slowNode` 的两倍。据此我们可以列出一个公式：(x+y)*2=x+n(y+z)+y，整理一下得到：x=n (y + z) - y，再从n(y+z)中提出一个 (y+z)来，整理公式之后为如下公式：**x=(n - 1) (y + z) + z**（注意这里n一定是大于等于1的，因为 `fastNode` 指针至少要多走一圈才能相遇`slowNode` 指针）。从这个公式可以发现，从头结点到环形入口节点的距离等于(n-1)圈的环形长度加上从相遇节点到环形入口节点的距离，也就是说假设我从头结点开始出发，你从相遇节点开始出发，我们俩的速度相同，当你走了(n-1)圈的环形长度的时候，你就回到了你出发的节点，也就是相遇的那个节点，距离环形节点还有z的距离。而我也走了(n-1)圈的环形长度，但是我距离环形入口节点还有z的距离（也就是还没进入环呢）。此时发现我俩都距离环形入口节点是z的距离，那么接下来只要我们的速度不变，后面一定能相遇。

不能理解？举个例子，假设n=3，那么x=(n - 1) (y + z) + z为x=2* (y + z) + z，如下图所示：

![image.png](142%20%E7%8E%AF%E5%BD%A2%E9%93%BE%E8%A1%A8II/image%201.png)

因此我们在`fastNode` 追上`slowNode` 的那个相遇节点设一个指针，在链表头结点也设置一个指针，两个指针同时移动，那么这两个指针相遇的节点一定是环形入口节点。完整代码如下：

```java
public class Solution {
    public ListNode detectCycle(ListNode head) {
        if (head == null || head.next == null) {
            return null;
        }

        ListNode slow = head;
        ListNode fast = head;

        // 第一步：判断是否有环
        while (fast != null && fast.next != null) {
            slow = slow.next;          // 慢指针走一步
            fast = fast.next.next;     // 快指针走两步

            // 如果快慢指针相遇，说明有环
            if (slow == fast) {
                // 第二步：寻找环的入口
                ListNode index1 = head;
                ListNode index2 = slow;
                
                // 两个指针分别从 head 和 相遇点出发，每次走一步
                while (index1 != index2) {
                    index1 = index1.next;
                    index2 = index2.next;
                }
                // 再次相遇的点即为环的入口
                return index1;
            }
        }

        return null; // 无环
    }
}
```

## 问题答疑

1. 为什么第一次在环中相遇，`slow`的步数 是 x+y 而不是 x + 若干环的长度 + y 呢？也就是说为什么`slow`一进入环，`fast`可以保证在一圈之内追上`slow`呢？

我的错误理解：因为`fast`的速度是`slow`的两倍，因此当`slow`走了半圈的时候，`fast`刚好走完一圈，而在这一圈内。也就是说`slow`还没走完半圈就肯定被`fast`给追上了。

实际上这样的理解是错误的，假设fast和slow目前在同一起始点同时起跑，然后当fast跑了一圈回到了原点，slow这时只跑了半圈，fast根本没追上slow，还需要半圈才追上。所以这么理解是错误的。正确的理解需要一些数学推导，看代码随想录关于该题的**补充部分：**https://programmercarl.com/0142.%E7%8E%AF%E5%BD%A2%E9%93%BE%E8%A1%A8II.html#%E7%AE%97%E6%B3%95%E5%85%AC%E5%BC%80%E8%AF%BE

1. 我之前的错误解法：先找到相遇的节点，然后将相遇节点设为链表2的头结点，相遇节点前一个节点的`next`设为`null` ，也就是将链表切断一分为二。这时就有了两个链表，可以发现问题就回到找两个链表相交的节点，岂不美哉。但是事实上行不通。考虑一种极端情况：两个节点相遇的那个点刚好是环形入口的那个点，那么将这个点的前一个点（不管是环外那个还是环内这个）的next设为null就会导致链表断裂。
2. 在环中fast去追slow的时候，为什么fast不可能跳过slow，从而错过slow呢？

因为slow的速度是1，而fast的速度是2，即他们两的相对速度是1，因此每走一次，这两个节点的相对位置就靠近一格，即fast是每次减少一格的方式来靠近slow的。举个例子就很好理解了。
