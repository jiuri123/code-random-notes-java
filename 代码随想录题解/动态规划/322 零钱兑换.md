# 322. 零钱兑换

[https://leetcode.cn/problems/coin-change/description/](https://leetcode.cn/problems/coin-change/description/)

其实挺简单的一道题，刚开始我的思路其实是对的，但是后面又被带偏了，导致思路走错。下面先看正确的解法，然后在说说我的错误解法。

动规五部曲第一步（发现自己不喜欢按照动规五部曲来分析，所以效率很低，一定要严格按照规则来啊），确定dp数组以及下标的含义，`dp[j]`可以表示成凑成面额为`j`所需的硬币数最小是`dp[j]`。

第二步确定递归公式，对于每一个`dp[j]`要么是取当前的硬币，要么是不取，就看看这两种情况那种情况所需要的硬币数量最小，就取哪种方法的硬币数，所以递推公式如下：`dp[j] = Math.min(dp[j], dp[j - coin] + 1);`。

第三步dp数组初始化，`dp[0]`表示没有任何硬币可以选择的情况下，凑出面额为0所需的硬币数最小是多少，很明显不需要任何硬币数就可以凑出0元的面额，因此`dp[0]`应该初始化为0。而又因为递推公式中用到了`Math.min`，所以`dp`数组的其他位置就不应该像前面那样直接初始化为0，而是需要初始化为一个最大值，比如`Integer.MAX_VALUE`或者`amount + 1`（面额为1所需的硬币数），不然比较的过程中就会将所有的`dp[j]`都变成`0` 。

第四步是确定遍历顺序，本题不涉及求组合还是排列问题，因此内外循环可以随意变换，同时每个硬币数量无限，是完全背包问题，因此内循环需要顺序遍历。第五步省略，代码如下：

```java
class Solution {
    public int coinChange(int[] coins, int amount) {
        // 初始化 DP 数组，dp[j] 表示凑成金额 j 所需的最少硬币数量
        int[] dp = new int[amount + 1];
        // 将所有金额的初始值设为一个不可能的大值，比如 amount + 1
        // 因为所需硬币的数量最多就只可能是 amount（此时每个币的币值是1）
        // 不能初始化为 Integer.MAX_VALUE，否则计算 dp[i - coin] + 1 时会溢出为负数
        Arrays.fill(dp, amount + 1);
        // 金额 0 不需要硬币
        dp[0] = 0;
        
        for(int i = 0; i < coins.length; i++){ // 外循环遍历物品（硬币）
            for(int j = coins[i]; j <= amount; j++){ // 内循环遍历背包（目标金额）
                dp[j] = Math.min(dp[j], dp[j - coins[i]] + 1);
            }
        }

        // 如果 dp[amount] 仍然是初始值，说明无法凑成目标金额
        return dp[amount] > amount ? -1 : dp[amount];
    }
}
```

也可以进行剪枝操作：

```java
// 遍历每种硬币
for (int coin : coins) {
    // 对于每个硬币，更新从 coin 到 amount 的所有可能金额
    for (int j = coin; j <= amount; j++) {
        if (dp[j - coin] != amount + 1) { // 剪枝操作
        // 如果 j - coin 可以凑成，则尝试更新 dp[j]
            dp[j] = Math.min(dp[j], dp[j - coin] + 1);
        }
    }
}
```

`dp[j - coin] != amount + 1` 说明无法用现有的硬币凑出`j - coin` 的面额，因此也就没有比较的必要了，等于是直接将`dp[j]` 赋值为`dp[j]`。

我之前的错误想法是觉得既然是求**可以凑成总金额所需的最少的硬币个数**，那肯定就是先尽可能多的选取当前可以选择的硬币中币值最大的，选完之后肯定还剩下一点面额，就继续尽可能多的选取币值第二大的硬币将这个面额填满，否则就继续这个过程，直到面额被填满（填不满说明凑不出面额，填-1）。但是这样很明显这个思路是错误的，考虑下面这个情况：`coins = [1, 3, 4], amount = 6`，按照我的思路很可能答案是3（选择一个4和两个1），但是答案其实是2（选择两个3）。所以不一定疯狂选币值最大的就可以使得凑成总金额的硬币个数最少，因此不可以使用贪心算法！

易错点：不能初始化为 `Integer.MAX_VALUE` 。因为在 `dp[i - coin] + 1` 计算时，如果是 `MAX_VALUE` 会产生溢出变成负数，导致循环结束后dp里的所有值都是-2147483647（Integer.MAX_VALUE + 1）。
