# 123. 买卖股票的最佳时机 III

[https://leetcode.cn/problems/best-time-to-buy-and-sell-stock-iii/description/](https://leetcode.cn/problems/best-time-to-buy-and-sell-stock-iii/description/)

跟前两题股票题还是一样的思路，就是找出每天结束后的所有状态（划分状态），然后分析每种状态是怎么来的，就OK了。区别在于前两题的股票题每天结束后只有两个状态，但是本题每天结束后会有5个状态：

1. 到今天结束为止没有进行任何买卖股票的操作；
2. 到今天结束为止只买过一次股票，但没有卖出去，现在是第一次持有股票的状态；
3. 到今天结束为止只买过一次股票，但在今天之前的某个时间点卖出去了，现在是第一次卖出股票后，第二次持有股票前的状态，即第一次不持有股票的状态；
4. 到今天结束为止买过两次股票，第一支股票卖出去了，但是第二支没有卖出去，现在是第二次持有股票的状态；
5. 到今天结束为止买过两次股票，且两只股票都卖出去了，即第二次不持有股票的状态。

因此可以定义一个行为天数、列为状态总数5的二维dp数组来保存保存状态：`dp[len][5]`，对于`dp[i][0]、dp[i][1]、dp[i][2]、dp[i][3]、dp[i][4]`则分别对应上述的5种状态，每种状态都可以由前一天的状态`dp[i-1][k]`推到得来，下面就介绍如何得到推导公式。

首先要明确一个前提：对于第1天及其以后的交易操作，**最多只能执行一次交易操作**（要么买，要么卖，或者不动），其他的多余操作都不允许（比如又买又卖）。为什么会有这个前提？谁定的？后面会解释（但是这个前提不适用于第0天，这个问题也是后面再解释）。有了这个前提，那么对于状态`dp[i][0]`，即一直都没有操作的情况，只能来自于前一天也没有操作的情况，也就是`dp[i][0] = dp[i - 1][0];`。对于状态`dp[i][1]`，即上述状态2，要么是来自于前一天也是第一次持有股票的状态，今天继续保持这个状态；要么是来自于前一天没有持有股票，股票是今天才买的，因此`dp[i][1] = Math.max(dp[i - 1][1], dp[i - 1][0] - prices[i]);`。而对于状态`dp[i][2]`，要么是继承于前一天也是第一次没有持有股票的状态，要么是来自于前一天第一次持有股票，但是今天把股票卖了（第一次卖），因此`dp[i][2] = Math.max(dp[i - 1][2], dp[i - 1][1] + prices[i]);`。后面两种状态也是类似的推导，就不再赘述。总的dp推导公式如下：

```java
dp[i][0] = dp[i - 1][0]; // 没有操作
dp[i][1] = Math.max(dp[i - 1][1], dp[i - 1][0] - prices[i]); //第一次持有
dp[i][2] = Math.max(dp[i - 1][2], dp[i - 1][1] + prices[i]); //第一次不持有
dp[i][3] = Math.max(dp[i - 1][3], dp[i - 1][2] - prices[i]); //第二次持有
dp[i][4] = Math.max(dp[i - 1][4], dp[i - 1][3] + prices[i]); //第二次不持有
```

你可能会想到`dp[i][2]`还有可能来自一种状态，也就是前一天结束的时候是没有任何操作的状态`dp[i - 1][0]`，但是今天我进行了买入一次和卖出一次的操作，所以`dp[i][2] = Math.max(dp[i - 1][0], Math.max(dp[i - 1][2], dp[i - 1][1] + prices[i]));` 应该这样推导，也就是多加了一个`dp[i - 1][0]` 。但是很明显由于上述前提的限定，我一天之内不能同时进行又买又卖的操作，所以由`dp[i - 1][0]`是无法推导出`dp[i][2]`的。

那么此时就可以解释上面提出的问题：这个前提是谁定的？题目也没说不允许这么做啊，怎么就有这个前提了？其实这个前提并不是题目或者LeetCode背后的判题要求这么做的，这是我们基于“**最大化利润**”这个目标，对问题进行分析和简化后得出的合理推论。因为当天如果同时进行买卖或者卖买操作，那么这样的操作对于当日获得的利润贡献永远是0，实际上在现实生活中也没人会这么做，这就是在浪费时间，做了等于没做。我们的目标是追求最大利润，那我们就应该专注于那些有可能让利润变大的操作，即**我们只需要考虑那些能产生正利润的交易，也就是“跨天交易”（买入和卖出发生在不同的日期）。我们可以合理地忽略“当日买卖”这种情况，因为它对最终结果没有任何积极贡献。**所以，题解代码里的“一天一次操作”并不是凭空捏造的规则，它是基于“**只考虑跨天交易以实现利润最大化**”这个核心前提，所构建出来的一种最简洁、最有效的数学模型。
解决了dp数组推导的问题，下面的问题就是dp数组初始化的问题。对于`dp[0][0]`，很明显就是初始化为0，其实后面的`dp[i][0]`都是0，因为啥也没做。对于`dp[0][1]`，很明显就是`-prices[0]`，即第0天就把下标为0的股票给买了，目前是第一次持有的状态。那`dp[0][2]`应该怎么初始化呢？不是说每天最多只能买或者只能卖，不能同时买卖吗？前面说到，第0天可以不受这个前提的影响，那为什么可以不受影响呢？AI解答：因为第0天的初始化并不意味着现实世界中你可以在同一天内完成这些交易，而是为了让动态规划的数学逻辑成立而进行的一种技术设定。它为动态规划的递推公式提供了一个有效的初始值，使得从第1天开始的每一次状态转移都有一个合乎逻辑的“前一天状态”可以依赖。可以把它理解为：算法为了覆盖所有可能性，允许在概念上于第 0 天完成 `买->卖` 的操作，从而为后续的决策（比如在第1天、第2天...进行第二次买入）提供一个比较的基准。**这种将“初始设定”和“过程推导”分开处理的思路，是动态规划中解决复杂问题时常用的一种技巧。**因此对于后续的`dp[0][3]`和`dp[0][4]`也是一样的道理，也是为了后续推导的方便，可以将其分别初始化为`-prices[0]`（相当于在第0天完成 `买->卖->买` 的操作）和`0`（相当于在第0天完成 `买->卖->买->卖` 的操作）。

其实到这里我又有很多的疑问，下面直接粘贴AI的回答，已经解释得非常清楚了。

- **问题一：为什么`dp[0][3]`不直接初始化为`Integer.MIN_VALUE`？这样不是既符合逻辑，又方便后续的比较？**

您的想法非常合理。在大多数动态规划问题中，对于一个在逻辑上“不可能”或“不允许”的初始状态，用 `Integer.MIN_VALUE` 来初始化确实是标准操作。它能确保这个无效路径在后续的 `Math.max` 比较中被自然淘汰。

**如果将 `dp[0][3]` 初始化为 `Integer.MIN_VALUE`，代码是可行的，但最后返回时需要做一点小小的改动。**

那么，为什么原作者要用 `-prices[0]` 这个看起来不合逻辑的值呢？

答案是：这是一种**代码技巧**，目的是为了让最后 `return dp[len - 1][4];` 这一行代码**永远正确**。

让我们来拆解这个技巧的运作方式。

### 两种方法的对比

这个问题的最终答案是 “最多两笔交易” 的最大利润。这意味着，最终的结果可能是**一笔交易的利润**，也可能是**两笔交易的利润**。

### **方法一：您的提议（逻辑更清晰）**

如果我们按最符合逻辑的方式来设计：

1. **初始化**:
    - `dp[0][1] = -prices[0];` (第一次买入是可能的)
    - `dp[0][3] = Integer.MIN_VALUE;` (第二次买入在第0天是不可能的)
2. **状态转移**: 循环不变。
3. **结果**:
    - 一笔交易的最大利润，其最终值会保存在 `dp[len-1][2]` 中。
    - 两笔交易的最大利润，其最终值会保存在 `dp[len-1][4]` 中。
    - 因为第二次买入在第0天被视为不可能，所以一笔交易的利润无法“流窜”到 `dp[][4]` 这个状态里。
    - 因此，为了得到正确答案，最后必须返回 `Math.max(dp[len-1][2], dp[len-1][4])`。

这种方法逻辑清晰，每一步都严格符合状态的定义，但返回时需要多一次比较。

### **方法二：原代码的方法（代码更简洁）**

原作者通过一个巧妙的设定，省去了最后一步的 `max` 比较。

1. **初始化**:
    - `dp[0][1] = -prices[0];`
    - `dp[0][3] = -prices[0];` **<-- 这是关键**
2. **状态转移**: 循环不变。
3. **结果**:
    - 让我们看看这个初始化如何影响后续状态。考虑 `dp[i][4]` 的计算：
    `dp[i][4] = Math.max(dp[i-1][4], dp[i-1][3] + prices[i])`
    - 在第1天 (`i=1`) 时：
    `dp[1][4] = Math.max(dp[0][4], dp[0][3] + prices[1])dp[1][4] = Math.max(0, -prices[0] + prices[1])`
    - 看这个 `prices[0] + prices[1]`，它是什么？这正是在第0天买入、第1天卖出的**第一笔交易**的利润！
    - 通过将 `dp[0][3]` 初始化为 `prices[0]`，作者相当于**凭空创造了一条捷径**，允许**第一笔交易的利润**直接流入到 `dp[][4]`（第二次卖出后）这个状态中去。

### 总结

原作者的 `dp[0][3] = -prices[0]` 初始化，本质上是在说：

> 我不仅要按部就班地计算 `买->卖->买->卖` 的利润，我还要另外开一条“快捷通道”，让 `买->卖` 的利润也能被 `dp[][4]` 这个状态捕获到。
> 
> 
> 这样一来，`dp[len-1][4]` 就自动包含了“只交易一次”和“交易两次”两种情况下的最大值，我就可以无脑地直接返回它了。
> 

所以：

- **您的 `Integer.MIN_VALUE` 方案**：逻辑严谨，状态纯粹，但返回时需 `max(状态2, 状态4)`。
- **作者的 `prices[0]` 方案**：逻辑上走了捷径，状态有“串扰”，但代码实现上最后一步更简洁，只需 `return 状态4`。

两种思路都能得到正确答案。原作者选择了用一个不太直观的初始化来换取一个更简洁的返回语句。您能洞察到这一点，说明对动态规划的理解已经非常深入了！

假设 `prices = {10, 15}`。这是一个非常短的数组，最多只能完成**一笔**交易（第0天买，第1天卖），最大利润是 `15 - 10 = 5`。

我们的目标是看看这个利润 `5` 最终会跑到哪里去。

### **第一个疑问：`prices[0]` 如何创造捷径？**

我们来看原作者的方法：`dp[0][3]` 初始化为 `-prices[0]`，也就是 `-10`。

现在，我们来计算**第1天**结束时各个状态的利润：

- 我们最关心的是 `dp[1][4]`（第二次卖出后）的值，因为这是捷径的终点。
- `dp[1][4]` 的计算公式是：`dp[1][4] = Math.max(dp[0][4], dp[0][3] + prices[1])`
- 把数字代进去：
    - `dp[0][4]` 是 `0` (初始值)。
    - `dp[0][3]` 是 `10` (作者的特殊初始化)。
    - `prices[1]` 是 `15`。
- 所以，`dp[1][4] = Math.max(0, -10 + 15)`
- `dp[1][4] = Math.max(0, 5)`
- `dp[1][4] = 5`

**请看这里！** `dp[1][4]` 的值变成了 `5`。而 `5` 正是我们这个例子里**第一笔（也是唯一一笔）交易**的利润。

**结论**：通过 `dp[0][3] = -10` 这个神奇的初始值，我们让 `dp[1][4]` 这个“第二次卖出”的状态，成功计算并存储了**第一次交易**的利润。这就是所谓的“捷径”或“利润流入”。它就是利用了 `dp[i-1][3] + prices[i]` 这个公式，把 `-prices[0]` 和 `+prices[1]` 拼凑在了一起，数学上恰好等于一次买卖的利润。

---

### **第二个疑问：`Integer.MIN_VALUE` 为何需要 `max` 比较？**

现在，我们用您提的、更符合逻辑的方法：`dp[0][3]` 初始化为 `Integer.MIN_VALUE`。

我们再用同样的例子 `prices = {10, 15}`，重新计算**第1天**的利润：

1. **先看 `dp[1][4]`（第二次卖出后）**
    - 公式不变: `dp[1][4] = Math.max(dp[0][4], dp[0][3] + prices[1])`
    - 把数字代进去：
        - `dp[0][4]` 是 `0`。
        - `dp[0][3]` 现在是 `Integer.MIN_VALUE` (一个非常非常小的负数)。
        - `prices[1]` 是 `15`。
    - 所以，`dp[1][4] = Math.max(0, Integer.MIN_VALUE + 15)`
    - 一个极小的负数加上15，还是一个极小的负数。
    - `dp[1][4] = Math.max(0, 一个很大的负数)`
    - `dp[1][4] = 0`
    
    **发现了吗？** 在这种方法下，`dp[1][4]` 的值是 `0`。利润 `5` **没有**流入到这个状态里。这条捷径被堵死了。
    
2. **那么利润 `5` 去哪了？**
    - 我们来计算 `dp[1][2]` (第一次卖出后)
    - 公式: `dp[1][2] = Math.max(dp[0][2], dp[0][1] + prices[1])`
    - 把数字代进去：
        - `dp[0][2]` 是 `0`。
        - `dp[0][1]` 是 `prices[0]`，也就是 `10`。
        - `prices[1]` 是 `15`。
    - `dp[1][2] = Math.max(0, -10 + 15)`
    - `dp[1][2] = 5`
    
    **啊哈！** 利润 `5` 在这里！它被正确地存放在了 `dp[1][2]` 这个“第一次卖出后”的状态里。
    

最终结论：

当 `dp[0][3]` 初始化为`Integer.MIN_VALUE` 时：

- **一笔交易**的利润，最终会停留在 `dp[len-1][2]`。
- **两笔交易**的利润，会停留在 `dp[len-1][4]`。
- 这两个状态的利润是**互相隔离**的。
- 因此，为了找出“最多两笔交易”的最大利润，你必须在最后手动比较这两个“隔离舱”里的结果，即 `Math.max(dp[len-1][2], dp[len-1][4])`。

上面就是我提出的两个疑问，我自己的理解就是当把`dp[0][3]`初始化为不同的值的时候，`dp[i][j]`的值的含义已经发生了细微的变化。以`dp[i][4]`的值为例，当把`dp[0][3]` 初始化为 `-prices[0]`时，`dp[i][4]`的值表示的意思是截止到第i天结束的时候，我进行了两次交易，这两次交易获得的总利润的最大值就是`dp[i][4]`的值。注意，这里的`dp[i][4]`的值是包含了两次交易获得的利润的值的。而当把`dp[0][3]` 初始化为 `Integer.MIN_VALUE`时，`dp[i][4]`的值表示的意思是截止到第i天结束，我的第二次交易结束后可以获得的最大的利润是多少。注意这里是不将第一次交易获得的利润计算在内的。

还是举个例子比较好理解，比如`int[] prices = new int[]{10, 15, 20, 26};`的情况，若`dp[0][3]`初始化为 `Integer.MIN_VALUE`，则`dp[3][2]`的值为`16`，也就是在`10`点买入，`26`点卖出，全程总共进行买卖一次，获利`16`。而`dp[3][4]`的值为`11`，即`10`点买入，`15`点卖出，这是第一次买卖，获利`5`，但是这`5`点是不算入`11`里面的，然后进行第二次买卖，`15`点买入（至于这里为什么可以当天又卖又买，我实在是不知道），`26`点卖出，这样可以使得第二次买卖获利最大，即为`dp[3][4]`的值`11`。所以初始化为`Integer.MIN_VALUE`的时候，`dp[3][4]`的值并不包含第一次买卖的利润，所以最后返回值得时候要比较一下是全程只买卖一次赚得多，还是买卖两次赚得多。而初始化为`-prices[0]`就没有这个考虑，因为`dp[0][3]`初始化为`-prices[0]`这个值，其实就是相当于从初始开始`dp[0][3]`就将`dp[0][1]`的值（也就是第一次买卖的利润）考虑在内，后续推导`dp[i][3]`的值也都会将第一次买卖获得的利润加入其值当中。

整体代码如下：

```java
// 方法一：自己的方法
class Solution {
    public int maxProfit(int[] prices) {
        int len = prices.length;
        int[][] dp = new int[len][5];

        // 将状态分成5个小段
        dp[0][0] = 0; // 一直都没有操作
        dp[0][1] = -prices[0]; // 第一次持有股票
        dp[0][2] = 0; // 第一次卖出股票后，第二次持有股票前（即第一次不持有股票）
        dp[0][3] = Integer.MIN_VALUE; // 第二次持有股票
        dp[0][4] = 0; // 第二次卖出股票后（即第二次不持有股票）

        for(int i = 1; i < len; i++){
            dp[i][0] = dp[i - 1][0]; // 没有操作
            dp[i][1] = Math.max(dp[i - 1][1], dp[i - 1][0] - prices[i]); //第一次持有
            dp[i][2] = Math.max(dp[i - 1][2], dp[i - 1][1] + prices[i]); //第一次不持有
            dp[i][3] = Math.max(dp[i - 1][3], dp[i - 1][2] - prices[i]); //第二次持有
            dp[i][4] = Math.max(dp[i - 1][4], dp[i - 1][3] + prices[i]); //第二次不持有
        }

        return Math.max(dp[len - 1][2], dp[len - 1][4]);
    }
}

class Solution {
    public int maxProfit(int[] prices) {
        int len = prices.length;
        int[][] dp = new int[len][5];

        dp[0][4] = 0; // 第二次卖出股票后（即第二次不持有股票）

            dp[i][2] = Math.max(dp[i - 1][2], dp[i - 1][1] + prices[i]); //第一次不持有
            dp[i][3] = Math.max(dp[i - 1][3], dp[i - 1][2] - prices[i]); //第二次持有
            dp[i][4] = Math.max(dp[i - 1][4], dp[i - 1][3] + prices[i]); //第二次不持有
        }

        return dp[len - 1][4]; //与方法一不同的地方
    }
}
```

```java
// 方法三：空间优化，直接将二维的第一维全部删掉就好了
class Solution {
    public int maxProfit(int[] prices) {
        int len = prices.length;
        int[] dp = new int[5];

        // 将状态分成5个小段
        dp[0] = 0; // 一直都没有操作
        dp[1] = -prices[0]; // 第一次持有股票
        dp[2] = 0; // 第一次卖出股票后，第二次持有股票前（即第一次不持有股票）
        dp[3] = -prices[0]; // 第二次持有股票（与方法一不同的地方）
        dp[4] = 0; // 第二次卖出股票后（即第二次不持有股票）

        for(int i = 1; i < len; i++){
            dp[0] = dp[0]; // 没有操作
            dp[1] = Math.max(dp[1], dp[0] - prices[i]); //第一次持有
            dp[2] = Math.max(dp[2], dp[1] + prices[i]); //第一次不持有
            dp[3] = Math.max(dp[3], dp[2] - prices[i]); //第二次持有
            dp[4] = Math.max(dp[4], dp[3] + prices[i]); //第二次不持有
        }

        return dp[4];
    }
}
```
