# 300. 最长递增子序列

![image.png](300%20%E6%9C%80%E9%95%BF%E9%80%92%E5%A2%9E%E5%AD%90%E5%BA%8F%E5%88%97/image.png)

直接按照动规五部曲来分析：

## 方法一：动规

首先是`dp[i]`的定义，将`dp[i]`定义为**`i`之前（包括`i`）组成的子序列中，以`i`结尾的最长严格递增子序列的长度。**注意，这里的最长严格递增子序列的结尾必须是**`nums[i]`**，除了结尾之外的其他位置的元素不要求连续（这里是与下题[**674. 最长连续递增序列**](674%20%E6%9C%80%E9%95%BF%E8%BF%9E%E7%BB%AD%E9%80%92%E5%A2%9E%E5%BA%8F%E5%88%97.md) 的主要区别，另外后面会解释`dp[i]`为什么必须要定义成**以`i`结尾**）。同时还要注意，由于这里的`dp[i]`的值表示的这个最长子序列，其结尾一定是`nums[i]`。所以最后返回答案的时候应该是返回dp数组中的最大值，而不是`dp[len-1]`，因为最长严格递增子序列不一定是以`nums[len-1]`这个元素结尾的。举个例子：`[4, 5, 6, 3]`，这里,最终的`dp[len-1]`的值为`1`，而答案应该是`3`，也就是应该返回`dp[2]`这个值才对（也就是`6`的位置，此时最长长度为`3`）。

接下来是状态转移方程，对于`dp[i]`的计算，我们需要遍历`i`之前的所有位置`j`（不包括i，即`0≤j≤i-1`），如果`nums[i] > nums[j]`，那么说明以`nums[j]`结尾的最长子序列的后面，还可以再加上一个`nums[i]`，使得整体的长度加1。因为要求最长的长度，所以`nums[i]` 要存的是最大值，所以每次都要和`nums[i]`进行比较。因此递推公式为：`if (nums[i] > nums[j]) dp[i] = max(dp[i], dp[j] + 1);`

然后是初始化的问题，由于开始时每个元素都至少可以自己组成为一个递增子序列，所以初始时每个位置都应该初始化为长度1。

最后就是遍历顺序和举例推导，比较简单，就不解释了。整体代码如下：

```java
// 时间复杂度：O(N^2)
// 空间复杂度：O(N)
class Solution {
    public int lengthOfLIS(int[] nums) {
        int len = nums.length;
        int[] dp = new int[len];
        // 笨拙的初始化方法
        // for(int i = 0; i < len; i++){
        //     dp[i] = 1;
        // }
        Arrays.fill(dp, 1); // 初始化为1

        int res = 1; // 记录dp数组最大值
        for(int i = 1; i < len; i++){
            for(int j = 0; j < i; j++){
                if(nums[i] > nums[j]){
                    dp[i] = Math.max(dp[i], dp[j] + 1);
                }
            }
            res = Math.max(res, dp[i]); // 更新最大值
        }
        
        return res;
        // 不是返回dp[len - 1];，这是错误的
        // 因为最长严格递增子序列不一定是以nums[len - 1]结尾的
    }
}
```

那么问题来了，为什么非得将`dp[i]`定义成在`nums[0~i]` 这个范围内，**以 `nums[i]` 这个元素结尾**的最长递增子序列的长度？我难道不可以将`dp[i]`直接定义成`nums[0~i]` 这个范围内的最长递增子序列的长度吗？这样定义的话，我就不需要定义一个`res`来记录最大值并返回了呀？我直接返回`dp[len - 1]`就好了呀？

这是十分错误的做法，因为这样定义无法记录中间状态，导致`dp[i]`无法由之前的状态推导出来，也就是说无法计算出`dp`的推导公式。假设我们现在正在计算`dp[i]`的值，此时我们需要知道`dp[i]`应该接在哪个已知的子序列的后面，也就是说我们需要明确的知道这个子序列最后一位那个数字是什么。但是这时问题就来了，由于`dp[i-1]` 只告诉我们 `nums[0~i-1]` 中 LIS 的**长度**，但完全没有提供这个 LIS 是**以哪个数字结尾的，**所以关于以哪个数字结尾的信息我们完全丢失了！使得我们无法计算`dp[i]` 的推导公式。也就是说如果我们只用 `dp[i]` 记录 `nums[0...i]` 范围内的最优解长度，就会丢失**所有子问题的结尾信息**，导致无法进行正确的状态转移。所以这样的定义无法解决本问题，只能是将`dp[i]`定义成以`i`结尾的最优子结构，这样就记录了后续计算所必需的关键信息。

也可以说限制本题需要将`dp`定义为以`i`结尾的原因是我需要将当前位置的元素和之前序列中的最后一个位置的元素进行比较，因此我的`dp`数组需要保留最后一位的信息，所以才将`dp`数组定义成以`i`结尾。**一句话：因为要进行元素比较，所以要定义成以`i`结尾。**

## 方法二（面试推荐）：贪心 + 二分查找

我们维护一个数组 `tails`，其中 `tails[i]` 表示在原数组中所有长度为 `i + 1` 的递增子序列中，**末尾元素最小** 的那个递增子序列的末尾元素的值。比如`tails[2]`的值如果为4，说明在原数组中所有长度为3的递增子序列中，末尾元素最小的那个递增子序列，它的末尾元素是4。

- **为什么要选最小的末尾？** 因为末尾元素越小，后面接新数字形成更长序列的可能性就越大（贪心思想）。
- **如何更新？** 遍历原数组 `nums`：
    1. 如果当前数字 `x` 比 `tails` 中所有元素都大，说明可以接在最长序列后面，长度加 1。
    2. 如果 `x` 较小，则在 `tails` 中找到第一个**大于或等于** `x` 的数字，并用 `x` 替换它。这样做是为了缩小该长度序列的末尾数值，而不改变当前已达到的最长长度，使得以该元素x结尾的那些序列，后面继续遍历数组中剩余元素的时候，接上新数字从而形成更长序列的可能性更大（贪心思想的体现）。

```java
// 时间复杂度：O(NlogN)
// 空间复杂度：O(N)
class Solution {
    public int lengthOfLIS(int[] nums) {
        if (nums == null || nums.length == 0) return 0;
        
        // tails[i] 表示在 nums 数组中那些长度为 i+1 的递增子序列中
        // 末尾元素最小的那个子序列的末尾元素的值，就是 tails[i] 的值
        int[] tails = new int[nums.length];
        int size = 0; // 当前有效 tails 的长度

        for (int x : nums) {
            // 使用二分查找在 tails 中找到第一个大于等于 x 的位置
            int i = 0, j = size;
            // 不断缩小包围圈，将第一个大于等于 x 的位置给挤出来
            while (i != j) {
                int m = (i + j) / 2;
                if (tails[m] < x) {
                    i = m + 1;
                } else {
                    j = m;
                }
            }
            
            // 更新 tails
            tails[i] = x;
            
            // 如果 x 是放在末尾，说明没找到第一个大于等于 x 的那个元素
            // 也就说明 x 比目前的 tails 中任何一个数都要大
            // 即说明找到了更长的序列，此时延长最长严格递增子序列的长度
            if (i == size) {
                size++;
            }
        }
        
        return size;
    }
}
```
