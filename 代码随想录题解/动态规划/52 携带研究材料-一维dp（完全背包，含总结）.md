完全背包问题二维dp转一维dp其实还比较简单，但是有两个超级大坑，搞了一天算是彻底搞明白了，但是这样感觉好浪费时间，以后还是适可而止，需要适当的忍受一下有些暂时想不通的问题。

完全背包二维dp转一维dp其实就是将原来行的维度进行压缩，即将`dp[i][j] = max(dp[i][j], dp[i][j - weight[i]] + value[i])`变成`dp[j] = max(dp[j], dp[j - weight[i]] + value[i])`（即将行维度删掉就可以了）。整体代码如下：

```java
// 方法二：完全背包的一维dp解法（外物品，内背包的常规解法）
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        int N = scanner.nextInt();
        int bagWeight = scanner.nextInt();

        int[] weight = new int[N];
        int[] value = new int[N];
        for (int i = 0; i < N; i++) {
            weight[i] = scanner.nextInt();
            value[i] = scanner.nextInt();
        }

        int[] dp = new int[bagWeight + 1];
        for (int i = 0; i < weight.length; i++) { // 先顺序遍历物品
            for (int j = 0; j <= bagWeight; j++) { // 再顺序遍历背包
                if (j >= weight[i]) { // 保证背包装得下
                    dp[j] = Math.max(dp[j], dp[j - weight[i]] + value[i]);
                }
            }
        }

        System.out.println(dp[bagWeight]);
        scanner.close();
    }
}
```

开始解释上面说到的两个超级大坑：内循环遍历顺序以及内外循环可交换的问题：

1. **完全背包一维dp不管是遍历物品，还是遍历背包容量，都必须是正序遍历。**这点其实和完全背包二维dp一样，直接将一维dp放到二维dp中，然后根据“更新当前位置需要用到左边的值和上边的值”这点去理解。下面解释背包容量为什么必须是正序遍历。因为从完全背包的二维dp可知，更新当前位置使用到的值是当前位置左边的值和当前位置上边的值，所以在完全背包的一维dp中如果是从小到大进行遍历的话，则当前位置左边的值就表示的是已经更新过的值，这些值在二维dp中就表示当前位置左边的那值（更新表示将左上角的值下移，此时一维dp存的就是左边的值）。但是如果是像0-1背包内循环从大到小遍历的话，此时一维dp左边的值是没有更新过的，在二维dp中就是左上角的值，很明显与完全背包求当前位置的逻辑不同（需要用到左边位置的值）。所以对背包容量的遍历一定是要正序遍历的，这样我才能使用到左边的值而不是左上角的值来更新当前位置（这点其实通过联系二维dp也很容易理解）。
2. **保证不管是遍历物品还是遍历背包，都必须是正序遍历的前提下，完全背包一维dp的内外循环是可以更换顺序的（**也就是先遍历背包还是先遍历物品都是可以的）。先遍历物品再遍历背包就不解释了，这是常规解法，在二维dp中相当于先从左到右、再从上到下进行遍历。但是如果更换顺序，就是先遍历背包，再遍历物品（即先从上到下、再从左到右），这样也是可以的。即使这时候更新`dp[j]`用到的是**左下角**和**上面的值**（为什么用的是左下角的值？因为此时对于一个背包容量，都会将每一个物品都看一遍（即内循环对所有物品遍历一轮），然后将背包容量增加1，并进入下一轮内循环（又将所有物品都看一遍）。即此时`dp[j]`左边的值是已经遍历完所有的物品后最终的值，也就是相当于二维dp中的`dp[n][j - weight[i]]`，即最下面那行的那些值）。可是由之前的推导更新`dp[j]`不应该用的是左边的值和上面的值吗？是的没错，但是用当前位置的左下角底边的值和上面的值来进行更新也是可以得到正确的最终答案，只不过在运行过程中`dp[j]`的值已经无法映射到二维dp中相应的位置，即某些值已经不符合实际逻辑。
    - 举个例子，假如：`weight = [1,2,3,4]；value = [10, 21,30,43]；bagWeight = 5`。通过常规的二维dp（外物品，内背包）求得的二维dp数组如下：

    - 但是通过外背包，内物品的一维`dp`求得的`dp`数组中第一行的`30,40,50`分别是`31,41,53`（另外还有两个错误的位置就不标出来了）。也就是说通过交换内外循环的位置后的一维dp得到的中间结果是错误的，是不符合`dp`数组的定义的，**或者说此时的`dp[j]`应该定义为所有物品皆可以选择的情况下，背包容量为j的背包此时可以存的总价值是多少**。以上面第二行的52举例吧，在一维`dp`中这个是`53`，是一个错误的中间结果。此时`dp[5] = max(dp[5], dp[5 - 2] + value[1])`，可以看到`dp[5 - 2]`使用的是左下角最底边的那个值，也就是最后一行的`31`，这个`31`表示的是背包容量为`3`且所有物品都可以选择的情况下，背包可以达到的最大价值是`31`。而`dp[5 - 2]`后面再加一个`value[1]`表示的就是此时再加一个物品1，其价值总和与`dp[5]`（目前`dp[5]`的值是刚刚遍历物品0后更新过后的值）进行比较。所以此时的dp的值已经变味了，是已经考虑了所有的物品的情况下的最大价值（或者说某些中间结果的意思已经变成了考虑过所有物品的情况下的价值，但可能并非最大，因为要遍历完当前列才知道当前位置是否是价值最大的值），但是并不影响最后的结果是正确的。
    - 说白了，每一次每列遍历下去就是想看看在这样的背包容量下，到底是放物品1价值大，还是放物品2价值大……依次类推。也就是说完全背包里面需要的是`j - weight[i]`容量里面的最大值，不需要考虑到底是前几个物品组成的最大值。所以最后的`dp[n - 1][bagWeight]`就也可以得到最终的结果。

交换内外循环后的代码如下：

```java
// 方法二：完全背包的一维dp解法（交换内外循环的顺序，即外容量，内物品）
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        int N = scanner.nextInt();
        int bagWeight = scanner.nextInt();

        int[] weight = new int[N];
        int[] value = new int[N];
        for (int i = 0; i < N; i++) {
            weight[i] = scanner.nextInt();
            value[i] = scanner.nextInt();
        }

        int[] dp = new int[bagWeight + 1];
        for (int j = 0; j <= bagWeight; j++) { // 先顺序遍历容量
		        for (int i = 0; i < weight.length; i++) { // 再顺序遍历物品
                if (j >= weight[i]) { // 保证背包装得下该物品的前提下
                    dp[j] = Math.max(dp[j], dp[j - weight[i]] + value[i]);
                }
            }
        }

        System.out.println(dp[bagWeight]);
        scanner.close();
    }
}
```

**总结：**由于完全背包的特殊性质（每个物品有无数个，每个物品都可以被选择多次），导致不管是用左边和上边的值来更新当前的位置，还是用左下角底边的值和上边的值来更新当前的位置，最终都可以得到正确的答案。

**最佳实践：**外循环**顺序**遍历**物品**，内循环**顺序**遍历**背包**。
