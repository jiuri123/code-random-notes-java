# 459.重复的子字符串

![image.png](459%20%E9%87%8D%E5%A4%8D%E7%9A%84%E5%AD%90%E5%AD%97%E7%AC%A6%E4%B8%B2/image.png)

本题主要是判断一个字符串是否是由它的一个子串重复多次构成。有如下三种解法。

**解法一：暴力解法。**取出每个可能的子串，然后重复多次构成与主串长度相同的另一个主串，看两者是否相同即可。代码如下：

```java
// 方法一：暴力解法
class Solution {
    public boolean repeatedSubstringPattern(String s) {
        for(int i = 1; i <= s.length() / 2; i++){ 
		        //取本次循环要判断的子串subStr
            String subStr = s.substring(0, i);
            //若主串长度不能被子串长度整除，说明不可能由这个子串重复多次构成
            if(s.length() % subStr.length() != 0){
                continue;
            }
            int repeatNum = s.length() / subStr.length(); //计算重复次数
            StringBuilder sb = new StringBuilder();
            for(int j = 0; j < repeatNum; j++){
                sb.append(subStr);
            }
            if(sb.toString().equals(s)){
                return true;
            }
        }
        return false;
	    }
}
```

可以看到第一个`for`循环的i表示的是子串的末尾位置，而`i`只需要移动到主串的中间位置就可以了，因为当子串长度超过主串的二分之一时，就不可能由这个子串重复组成主串，所以符合条件的子串的长度必须要小于等于主串长度的一半。

还有就是为什么选取子串的时候，起始位置可以直接从`0`开始，也就是为什么子串永远是主串的某个前缀？因为如果子串可以经过重复操作构成主串的话，那么某个前缀一定可以找到这个子串。如果所有的前缀都找不到符合条件的子串，那么只能说明不存在这样的子串，可以使得重复操作组成主串。

**解法二：移动匹配。**移动匹配基于这样一个事实：**若可以在拼接后的字符串`str+str`的除了前后两个`str`中还能找到一个`str`，那就说明字符串`str`一定是由它的某个子串重复多次构成。**为什么可以这样呢？我们来看`str="abcabc"`的情况，此时`str+str="abcabcabcabc"`，可以发现在组成的新字符串中可以找到原来的`str`（也就是下划线部分），那么就说明`str`一定是由它的某个子串重复多次构成（即`abc`）。具体证明见[代码随想录](https://programmercarl.com/0459.%E9%87%8D%E5%A4%8D%E7%9A%84%E5%AD%90%E5%AD%97%E7%AC%A6%E4%B8%B2.html#%E6%80%9D%E8%B7%AF)的相关部分。代码如下：

```java
// 方法二：移动匹配
class Solution {
    public boolean repeatedSubstringPattern(String s) {
        String str = s + s;
        //去掉组合字符串的前后一个元素
        //也就是相当于破坏前后的s，使得后续不匹配前后的s
        str = str.substring(1, str.length() - 1);
        if(str.contains(s)){
            return true;
        }else{
            return false;
        }
    }
}
```

**解法三：KMP法。**KMP方法基于这样一个结论：如果一个字符串能通过它的某个子串（不唯一）重复多次组成，那么这个主串的**最小重复子串**一定是主串中不包含最长相等前后缀子串的剩余部分的这个子串。比如`ababab`的最长相等前后缀是`abab`，那么剩下的`ab`就是能够通过重复操作组成原来的主串，当然前提是知道原来的主串是通过它的某个子串重复得来的。那怎么得到这个前提呢：**当主串中除最长相等前后缀的剩下那个子串的长度能够被主串的长度整除时，说明这个剩余的子串是能够通过重复操作组成原来的主串的；若剩下那个子串的长度不能被主串的长度整除时，则主串不存在最小重复子串。**代码如下：

```java
// 方法三：KMP算法
class Solution {
    public boolean repeatedSubstringPattern(String s) {
        int[] next = new int[s.length()];
        getNext(s, next);
				// subStrLen表示的是剩余那个子串的长度
				// next[s.length() - 1]表示的是最长相等前后缀的长度
        int subStrLen = s.length() - next[s.length() - 1];
        // 当next[s.length() - 1] = 0时，说明剩余的子串就是主串，不成立，直接退出
        if(next[s.length() - 1] > 0 && s.length() % subStrLen == 0){
            return true;
        }else{
            return false;
        }
    }

		//求next数组
    public void getNext(String s, int[] next) {
        int j = 0;
        next[0] = 0;
        for(int i = 1; i < s.length(); i++){
            while(j > 0 && s.charAt(j) != s.charAt(i)){
                j = next[j - 1];
            }
            if(s.charAt(j) == s.charAt(i)){
                j++;
            }
            next[i] = j;
        } 
    }
}
```

两个问题：

1. 为什么如果一个字符串`s`是由重复子串组成，那么最长相等前后缀不包含的子串一定是字符串`s`的最小重复子串？

因为如果`s` 是由最小重复子串`p`组成，即 `s = n * p`，那么前`n-1`个`p`和后`n-1`个`p`就分别是前后缀，那剩下那个`p`就很明显就是主串的最小重复子串。为什么最长相等前后缀就不能更长一些？见[代码随想录](https://programmercarl.com/0459.%E9%87%8D%E5%A4%8D%E7%9A%84%E5%AD%90%E5%AD%97%E7%AC%A6%E4%B8%B2.html#%E6%80%9D%E8%B7%AF)。

1. 那为什么当最长相等前后缀不包含的那个子串的长度能被主串长度**整除**的时候，那么这个子串就一定是主串的最小重复单位（也就是说明了主串是含重复子串的）？看下图：

![6F1194F20B82C07A14280D17AE1FD913.png](459%20%E9%87%8D%E5%A4%8D%E7%9A%84%E5%AD%90%E5%AD%97%E7%AC%A6%E4%B8%B2/6F1194F20B82C07A14280D17AE1FD913.png)

可以看到`abababab`的最长相等前后缀是`ababab`，而不包含的部分是`ab`，也就是最小重复单位。此时`s01`的`ab`是等于`t01`的`ab`的（因为前后缀相等），而`t01`的`ab`对应的是`s23`的`ab`，而`s23`的`ab`是等于`t23`的`ab`的（因为前后缀相等）……以此类推，可以发现最小重复单位就是`ab`。也就是说只有在剩余的子串能被主串整除的情况下，才可以通过上面的`s01`一路推导下去直到末尾（且没有剩余字符没有被推导过），这时才能说明剩余子串能被整除的情况下确实就是主串的最小重复单位。也就是解决了这个问题：最长相等前后缀不包含的子串什么时候才是字符串`s`的最小重复子串呢。答：能被整除的情况下（不能被整除的情况说明主串不含重复子串）。

即我通过最长相等的前后缀找出了可能是最小的重复子串（这个一定是最小的，因为不是最小的话，说明前面给出的最长相等前后缀并不是最长的前后缀，这就出现了矛盾），然后如果可以通过这个可能是最小的重复子串将整个字符串推导出来，那就说明字符串是可以通过某个子串重复拼接而来，否则就不行。
