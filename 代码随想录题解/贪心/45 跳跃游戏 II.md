# 45. 跳跃游戏 II

[https://leetcode.cn/problems/jump-game-ii/description/](https://leetcode.cn/problems/jump-game-ii/description/)

比[**55. 跳跃游戏**](55%20%E8%B7%B3%E8%B7%83%E6%B8%B8%E6%88%8F.md) 难了不少，主要思路就是每遍历到一个节点，就对这个节点所覆盖的范围内的所有节点进行遍历，找到这些节点中所能覆盖范围最远的那个节点（实际上就是找出能将当前节点所覆盖的范围向前推进最远距离，使得范围扩大得最大的那个节点）。下一跳就直接跳到这个节点，然后继续找新到达的这个节点所覆盖的范围内的那些节点中所能覆盖范围最远的那个节点，下一条就跳来这个节点……依次循环，直到到达终点位置为止。每次都跳到当前节点覆盖范围的节点当中覆盖范围最远的那个节点，这就是这道题所体现出来的贪心思想。

具体的实现当然可以两层循环，第一层循环遍历每个节点（这里不一定会对所有节点进行遍历，后面会提到），第二层循环对遍历到的每个节点，找出这个节点所覆盖范围内的节点当中那个覆盖范围最大的节点，然后下一跳直接到这个节点。因为要找最大，所以第二层循环得对当前节点所能覆盖范围的所有节点都要遍历一遍，但是第一层循环可以直接从第二层循环结束后找到的那个节点开始遍历，不需要所有节点都遍历一遍。但是这里面有很多的重复元素的遍历，发生在第二层循环，因为在第二层循环结束后，第一层循环需要一个新的起始点，这个起始点有可能是在之前那个节点所覆盖范围中间的某个节点，然后从这个节点开始进行第二个循环，此时重复遍历就发生了，也就是这个新节点第二轮循环的前半段与上一个旧节点第二轮循环的后半段出现重复遍历，导致不必要的时间浪费。这完全是可以避免的，下面介绍的第二种解法其实是对第一种解法进行改进。

可以发现对重复元素的遍历发生在第二轮循环，因为每次第二轮循环都要从头开始，那能不能不让这个第二轮循环从头开始？当然可以，反正我对每个节点的遍历只是需要知道这个节点所能到达的最远范围，而这个最远范围只需要将数组元素和数组下标相加起来就可以了，然后用一个变量记录这些节点中最远的那个范围就行。因此我可以直接使用第一轮循环的索引值来判断我的第二轮循环是否到达终点，此时第二轮循环被改造成了一个`if`语句，同时需要两个变量分别记录当前节点所能到达的范围以及当前节点所能到达的范围当中的那些节点所能到达的最远范围，可以发现每次第二轮循环的起始点实际上已经变成了上一个节点所能覆盖范围的最后那个节点的下一个位置，这样就避免了对元素的重复遍历。整体代码如下：

```java
class Solution {
    public int jump(int[] nums) {
        // 如果数组长度为1，无需跳跃，直接返回0
        if (nums.length == 1) {
            return 0;
        }
        
        // 对初始状态的理解：
        // 初始时刚刚从飞机跳伞降落，此前还没有起跳过，因此 jumps = 0
        // 而且初始只能降落在下标0的位置，因此 currentMaxReach = 0
        // 因此下标0的值就是第一次跳所能到达的最远距离，即 nextMaxReach = nums[0]
        int jumps = 0; // 起跳次数
        int currentMaxReach = 0; // 当前起跳后所能降落的最远下标
        int nextMaxReach = nums[0]; // 下一次起跳所能覆盖的最远下标

        // 注意：我们不需要遍历最后一个元素，因为题目保证能到达
        // 如果我们恰好到达了最后一个元素的前一个位置，边界就会刚好覆盖终点
        for (int i = 0; i < nums.length; i++) {
            // 更新下一次起跳所能覆盖的最远下标
            // 此时还在空中，正在逐个遍历覆盖范围内的所有元素，寻找最佳降落位置
            nextMaxReach = Math.max(nextMaxReach, i + nums[i]);
            
            // 完成对当前覆盖范围内所有元素的遍历，已经确定降落位置
            if (i == currentMaxReach) {
                // 从空中降落到降落位置
                jumps++; // 同时立即又起跳到半空中
                currentMaxReach = nextMaxReach; // 更新这次起跳所能降落的最远距离
                
                // 如果此次起跳所覆盖的最远范围已覆盖终点，则结束循环
                if (currentMaxReach >= nums.length - 1) {
                    break;
                }
            }
        }
        
        // 返回最小跳跃次数
        return jumps;
    }
}
```

可以看到`break`之前不需要将`jumps`在加`1`，因为这里的`jumps`表示的是我跳`jumps`次，能到达的最远距离是`currentMaxReach，`从第一个点就可以推出这个规律。或者说`jumps++;`的意思是我在跳一次，我可以到达的最远距离变成了`currentMaxReach = nextMaxReach;`。当然也可以理解成我先跳到半空中了（`jumps++`），此时更新我这一跳能跳的最远范围（`currentMaxReach = nextMaxReach`），才开始找我接下来要跳去哪里（在空中找，不断更新`nextMaxReach`就是在找我要跳的那个目的点）。

那为什么 `currentMaxReach`和 `nextMaxReach`都初始化为0呢？初始化为0表示什么意思？

`currentEnd`表示当前跳跃覆盖范围的边界。初始化时，尚未进行任何跳跃，我就站在原点，因此覆盖范围仅限于起点（下标 `0`），所以 `currentEnd = 0`。`farthest`表示在当前覆盖范围内，所有节点能跳到的最远位置。初始时，只考虑起点（下标 `0`），尚未遍历任何节点，所以 `farthest`也初始化为 0，等待后续更新。

- `currentEnd = 0`：表示当前覆盖范围的边界是下标 0，即算法刚开始时只能站在起点，还没有扩展覆盖范围。
- `farthest = 0`：表示当前已知的最远可达位置是下标 0，因为还没有遍历任何节点来更新最远距离。
