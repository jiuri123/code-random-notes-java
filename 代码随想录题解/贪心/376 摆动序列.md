# 376. 摆动序列

[https://leetcode.cn/problems/wiggle-subsequence/description/](https://leetcode.cn/problems/wiggle-subsequence/description/)

本题有两种解法，第一种是求峰值（极值）的思想。也就是说摆动序列的长度其实就是峰值的个数，这里的峰值指的是极值，比如[1, 2, 1]就有三个峰值，因此摆动序列的长度就是3。那怎么计算峰值的个数呢？假如上一个峰值找到的是极大值，那么下一个就应该去找极小值，我们可以用一个preDiff表示上一个峰值的右边的差值（对于极大值来说就是下坡路，此时preDiff<0），然后去这个峰值的右边不断地找一个上坡路（curDiff>0），只要找到一个上坡路，那么就说明找到一个极小值的峰值，那么就可以更新preDiff为>0，然后继续去这个最小峰值的右边找下坡路，依次类推就可以把所有的峰值全部找出来。代码如下：

```java
// 方法一：算差值，找峰值思想
class Solution {
    public int wiggleMaxLength(int[] nums) {
        if(nums.length <= 1){
            return nums.length;
        }

        int preDiff = 0;
        int curDiff = 0;
        // 第0个点默认是峰值
        int count = 1;
        // 从第一个点开始遍历
        for(int i = 1; i < nums.length; i++){
            curDiff = nums[i] - nums[i - 1];

            // curDiff == 0的情况被直接跳过
            // preDiff = 0是为了处理初始情况
            // if的两个条件都说明出现了转折点
            if(curDiff > 0 && preDiff <= 0 || curDiff < 0 && preDiff >= 0){
                count++;
                preDiff = curDiff;
            }
        }
        return count;
    }
}
```

第二种方法有点类似于动态规划的思想，不太好理解。其实就是用两个变量up和down分别记录以上升结尾的最长摆动序列长度和以下降结尾的最长摆动序列长度，每找到一个上升点，就更新up的值为down+1，表示此时找到一个新的点可以作为原最长下降摆动序列的上升结尾点，此时原最长下降摆动序列升级为新的最长上升摆动序列。当找到一个下降点时也是同理。代码如下：

```java
// 方法二：类动态规划思想
class Solution {
    public int wiggleMaxLength(int[] nums) {
        if (nums.length == 0) return 0;
        if (nums.length == 1) return 1;
        
        int up = 1;   // 以上升结尾的最长摆动序列长度
        int down = 1; // 以下降结尾的最长摆动序列长度
        
        for (int i = 1; i < nums.length; i++) {
            if (nums[i] > nums[i-1]) {
                up = down + 1;
            } else if (nums[i] < nums[i-1]) {
                down = up + 1;
            }
        }
        
        return Math.max(up, down);
    }
}
```

从数组的第二个元素（i = 1）开始遍历，比较当前元素 nums[i] 和前一个元素 nums[i-1]：
• **如果 nums[i] > nums[i-1]**（当前元素比前一个大，形成上升趋势）：
    ◦ 这意味着可以将当前元素加入一个以**下降**结尾的子序列（down），形成一个新的以**上升**结尾的子序列。因此，up 更新为 down + 1。
    ◦ down 不变，因为当前上升趋势不会影响以下降结尾的子序列。
• **如果 nums[i] < nums[i-1]**（当前元素比前一个小，形成下降趋势）：
    ◦ 这意味着可以将当前元素加入一个以**上升**结尾的子序列（up），形成一个新的以**下降**结尾的子序列。因此，down 更新为 up + 1。
    ◦ up 不变，因为当前下降趋势不会影响以上升结尾的子序列。
• **如果 nums[i] == nums[i-1]**（当前元素等于前一个元素）：
    ◦ 代码中没有显式处理这种情况，但隐式地跳过了（不更新 up 和 down），这是正确的，因为相等元素不能形成摆动（差值必须严格为正或负）。每次循环只更新必要的状态，保持 up 和 down 跟踪最长的可能子序列。

那如果出现连续几个元素都是上升的情况怎么办？此时以下降结尾的最长摆动序列长度down不会出现变化（down只有在下降的时候值才会出现变化），那么up = down + 1;中的up也会一直保持不变，直到遇到下降的情况，此时更新down，因为此时找到一个新的以下降为结尾的序列，但是up还是不变，也就是说up和down只有在极值点处才会变化。
