本题主要求在一个数组中是否存在一个子数组（元素要连续，且相对位置不能改变），使得子数组的和大于给定值的同时子数组的长度也要最短。

首先最容易想到的就是暴力解法，就是先定子数组的左边界，然后在去找子数组的右边界，然后记录下子数组的最短长度。代码如下（来自随想录）：

```cpp
// 方法一：暴力解法
class Solution {
public:
    int minSubArrayLen(int s, vector<int>& nums) {
        int result = INT32_MAX; // 最终的结果
        int sum = 0; // 子序列的数值之和
        int subLength = 0; // 子序列的长度
        for (int i = 0; i < nums.size(); i++) { // 设置子序列起点为i
            sum = 0;
            for (int j = i; j < nums.size(); j++) { // 设置子序列终止位置为j
                sum += nums[j];
                if (sum >= s) { // 一旦发现子序列和超过了s，更新result
                    subLength = j - i + 1; // 取子序列的长度
                    result = result < subLength ? result : subLength;
                    break; // 因为我们是找符合条件最短的子序列，所以一旦符合条件就break
                }
            }
        }
        // 如果result没有被赋值的话，就返回0，说明没有符合条件的子序列
        return result == INT32_MAX ? 0 : result;
    }
};
```

暴力解法时间复杂度过高，为O($n^2$)，力扣无法通过，因此要换个思路。暴力解法时间复杂度过高的原因是遍历了一些可以通过已知条件推导出其和必不可能大于目标值的子数组。举个例子，假如我现在的左边界是0，右边界遍历到4的位置之后，此时的子数组的和刚好大于目标值。按照暴力解法，此时会将左边界向右移动一位，即到达1的位置，然后左边界也从1开始遍历。这就是问题所在，因为通过上一步已经知道，子数组[1, 3]的和是小于目标值的，那么这个子数组中的任意一个更小的子数组的和都一定是更加小于目标值的（前提：数组中所有的值都是正数）。因此对于现在即将比较的子数组[1, 1]、[1, 2]、[1, 3]等，都是在做毫无意义的遍历，这就是暴力解法时间复杂度高的真正原因。既然这样，那我是否可以这样优化：我的左边界不是单纯的每次向右移动一位，而是直接跳跃到一个必要的位置。因为我增加了一个右边界的值后，整体和超过了目标值，而此时如果我删去左边界的起始几个位置的值，子数组整体的和依然是有可能大于目标值的（比如新加入的右边界的值很大，但是左边界的几个值都很小），那左边界这几个起始值我都没有必要让左边界停留了，直接跳过就好。具体怎么判断左边界跳到那停止，可以通过判断当前子数组的和来解决。这就是下面要介绍的滑动窗口思路。

解决思路是用一个“叫做“**滑动窗口**”的东西。所谓滑动窗口，**就是不断的调节子序列的起始位置和终止位置，从而得出我们想要的结果**。思路有点像双指针解法。对于本题来说，就是用一个`for`循环来遍历数组，其索引为滑动窗口的结束位置，初始值为`0`。然后不断增加滑动窗口的大小，直到滑动窗口中元素的和大于等于给定的目标和，此时记录下这个可能是最小长度的子数组的长度。然后去移动滑动窗口的初始位置，即从初始位置开始不断地删掉滑动窗口中的元素，直到滑动窗口中元素的和小于给定的目标和，然后继续去移动滑动窗口的结束位置，如此循环往复，就可以得到长度最小的子数组的长度。

代码如下：

```java
// 方法二：滑动窗口
class Solution {
    public int minSubArrayLen(int target, int[] nums) {
        int left = 0; // 左边界
        int sum = 0; // 子数组的和
        int minLen = Integer.MAX_VALUE; // 记录最短的长度
        for(int right = 0; right < nums.length; right++){
            sum += nums[right]; // 不断延长右边界
            while(sum >= target){ // 直到子数组的和比目标值大
                // 记录最小长度
                minLen = Math.min(minLen, right - left + 1);
                sum -= nums[left++]; // 关键代码：缩短左边界
            }
        }

        if(minLen == Integer.MAX_VALUE){ 
            // 说明没有任何一个子数组的和比目标值大
            return 0;
        }else{
            return minLen;
        }
    }
}
```

**这段代码的关键点在于不断地根据当前子数组的和，来不断的动态调整左右边界的位置。**因此省略了一些子数组的检索步骤，**因为有些子数组完全没必要看。哪些子数组不用看？**如果某个子数组的和不大于等于`target`的话，那么其中更小的子数组就肯定更加不符合要求，因此这些更小的子数组就是可以直接跳过不用看的子数组。所以为什么循环内部的while循环一直缩短左边界，直到这个子数组的和小于目标值就停止了？因为此时这个子数组中更小的子数组的和只能是更小，因此更加不可能超过目标值，也就没有必要继续进行while循环来计算并判断子数组的和是否超过目标值了，这样就省去了很多不必要的检索步骤。

**那为什么在通过外部的for循环拓展了子数组的右边界之后，需要直接进入while循环去缩短子数组的左边界呢？**因为如果子数组在结束位置加一个元素之后就满足题目条件，这个新加入到右边界数有可能很大，即可能会导致子数组开始位置的几个元素没必要存在子数组中了，也就是值被抵消了，即可能可以通过去掉左边界开始的几个值来找到一个更短的子数组去满足题目的条件，所以用一个`while`循环去不断地缩短子数组的左边界来找到这个更优的子数组。

**这个移动窗口算法能保证所有的子数组都被检索到吗？**不能保证所有的子数组都被检索到。因为有可能右边界已经出界的时候，左边界还停留在数组中的某个位置。而且此时这个左右边界指向的子数组的和是小于目标值的，那么此时会直接退出for循环（因为这个子数组中的那些更小的子数组没必要去比较了呀），因此还有一些子数组没有被检索到。**但是**这个算法能保证所有和大于等于目标值的那些子数组都被检索到（以及一小部分和小于目标值的数组也能被检索到）。

滑动窗口解法将时间复杂度从O($n^2$)降到了O(n)（不要看到两个循环嵌套就是O($n^2$)，对于本题，大部分值都分别进入一次和退出一次子数组，因此时间复杂度为O(2n)）。
