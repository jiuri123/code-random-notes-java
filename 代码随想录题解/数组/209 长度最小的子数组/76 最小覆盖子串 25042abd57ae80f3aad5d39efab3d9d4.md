## 方法一

跟滑动窗口的思路差不多，大概就也是设置两个指针分别表示子数组的左右边界，然后不断的延长右边界，直到子数组可以刚好将字符串t覆盖。然后就开始移动子数组的左边界，直到子数组刚好无法将t覆盖，就再去移动子数组的右边界，不断循环上面的操作。移动子数组左边界的同时记录下子数组的最短长度。代码如下：

```java
// 方法一：常规解法，未优化覆盖检测算法
class Solution {
    public String minWindow(String s, String t) {
        // 记录最小覆盖子串的长度、左边界和右边界
        int minLen = Integer.MAX_VALUE, minLeft = 0, minRight = 0;
        // 用来统计t中各字母的出现次数
        HashMap<Character, Integer> tMap = new HashMap<>();
        for(int i = 0; i < t.length(); i++){ // 统计t中各字母的出现次数
            tMap.put(t.charAt(i), tMap.getOrDefault(t.charAt(i), 0) + 1);
        }

        // 用来存子串中，各字母的出现次数
        HashMap<Character, Integer> subtringMap = new HashMap<>(); 
        int left = 0; // 子串的左边界
        for(int right = 0; right < s.length(); right++){
            char rightChar = s.charAt(right);
            subtringMap.put(rightChar, subtringMap.getOrDefault(rightChar, 0) + 1);
            // 检查此子串能否覆盖t，如果能覆盖，就不断移动左边界，直到不能覆盖为止
            while(isSubstringContainT(subtringMap, tMap)){ // 调用函数
                // 先记录该子串的信息
                if(right - left + 1 < minLen){ 
                    minLen = right - left + 1; // 子串长度
                    minLeft = left; // 子串左边界
                    minRight = right; // 子串右边界
                }

                // 移动左边界
                char leftChar = s.charAt(left);
                subtringMap.put(leftChar, subtringMap.get(leftChar) - 1);
                if(subtringMap.getOrDefault(leftChar, 0) == 0){
                    subtringMap.remove(leftChar);
                }
                left++;
            }
        }

        // minLen == Integer.MAX_VALUE：s中不含一点t
        // minLen < t.length()：比如s是a，t是aa，即s含部分t，但是不能把t覆盖
        if(minLen == Integer.MAX_VALUE || minLen < t.length()){
            return "";
        }else{
            return s.substring(minLeft, minRight + 1);
        }
    }

    // 检测当前的子串能否覆盖字符串t
    public Boolean isSubstringContainT(HashMap<Character, Integer> substringMap, HashMap<Character, Integer> tMap){
        Set<Character> keys = tMap.keySet();
        for(Character ch : keys){
            if(substringMap.getOrDefault(ch, 0) < tMap.getOrDefault(ch, 0)){
                return false;
            }
        }
        return true;
    }
}
```

可以看到上面检测是否覆盖的算法是使用了两个哈希表来分别存储当前子数组各字母出现的个数以及字符串t中各字母出现的个数，然后对这两个哈希表进行比较就能得到是否覆盖。可以发现每次延长一次子数组的右边界和缩短一次左边界之后，都要重新去遍历一遍字符串t的哈希表，非常浪费时间，那有没有什么方法可以避免每次重新遍历呢？当然可以，下面的方法二就是对覆盖检测算法的优化。

## 方法二

首先定义一个变量typeGapCount表示在当前子数组中，还缺多少种（注意是多少种，而不是多少个）字母就可以将t覆盖（这个值初始化为t中字母的种类）。同时再定义一个哈希表typeGapMap表示缺的那些字母中，每种字母都具体都缺多少个。然后在滑动窗口算法中，当typeGapCount减小到0的时候，说明此时没有任何一种字母是缺的，也就是说目前的子数组是可以将t覆盖的，那么就进入移动子数组左边界的算法。移动左边界的时候也是，当typeGapCount的值超过0的时候，就说明子数组刚好缺其中一种字母的一个，就可以将t覆盖，然后就转去移动右边界，继续循环上面的操作。代码如下：

```java
// 方法二：优化覆盖检测算法
class Solution {
    public String minWindow(String s, String t) {
        // 记录还缺多少种字母就能将t覆盖
        int typeGapCount = 0;
        // 记录缺的那些字母中，每种字母还缺多少个
        // 可以认为是方法一中tMap - subtringMap（注意是相同元素相减）
        int[] typeGapMap = new int[128];
        // 将typeGap初始化为t中字母种类数，并统计每种字母缺多少个
        // 不缺的话就是0，如果是正数的话，说明是多出来的个数
        for(int i = 0; i < t.length(); i++){
            if(typeGapMap[t.charAt(i)] == 0){
                typeGapCount++; 
            }
            typeGapMap[t.charAt(i)]++;
        }

        // 记录最小覆盖子串的长度、左边界和右边界
        int minLen = Integer.MAX_VALUE, minLeft = 0, minRight = 0;

        int left = 0; // 子串的左边界
        for(int right = 0; right < s.length(); right++){
            char rightChar = s.charAt(right);
            // 如果本来就不缺的字母，typeGapMap[rightChar]的值为0，那么经过下面这句会变成负数
            // 如果本来是缺的字母，typeGapMap[rightChar]的值为正数，那么经过下面这句会变成正数或0
            typeGapMap[rightChar]--;
            if(typeGapMap[rightChar] == 0){ // 只有本来就缺的字母，才有可能进入这个循环
                typeGapCount--; // 有一种字母已经不缺了，因此缺的字母的种类-1
            }
            
            // 检查此子串能否覆盖t，如果能覆盖，就不断移动左边界，直到不能覆盖为止
            while(typeGapCount == 0){ // 说明此时不缺任何种类的字母了
                // 先记录该子串的信息，有可能是最短的子串
                if(right - left + 1 < minLen){ 
                    minLen = right - left + 1; // 子串长度
                    minLeft = left; // 子串左边界
                    minRight = right; // 子串右边界
                }

                // 移动左边界前，需要检查即将移出滑动串口左边界的那个字母
                char leftChar = s.charAt(left);
                // 同理，只有本来就缺的字母，才有可能进入下面这个循环
                // 其他不缺的字母，对应typeGapMap中的值都是负数，不可能是0或正数
                // 按这个例子：s = "AAABBCDAAA", t = "BBCD" 走一遍就知道为什么了
                if(typeGapMap[leftChar] == 0){ // 说明左边界移动到了第一个在t中出现的字符
                    typeGapCount++; // 则将所缺字母种类+1（简而言之，切到大动脉了）
                }
                // 记录还缺多少个左端点那种类型的字母就可以将t覆盖
                typeGapMap[leftChar]++;
                // 将左端点移出
                left++;
            }
        }

        // minLen == Integer.MAX_VALUE：s中不含一点t
        // minLen < t.length()：比如s是a，t是aa，即s含部分t，但是不能把t覆盖
        if(minLen == Integer.MAX_VALUE || minLen < t.length()){
            return "";
        }else{
            return s.substring(minLeft, minRight + 1);
        }
    }
}
```

这段代码还是比较难理解的，其中最难的是覆盖检测判断以及移动左边界的停止判断。如果不能理解，就用s = "AAABB**BBCD**AAA", t = "BBCD"走一遍，大部分问题都能解决。

总之就是初始化后的typeGapMap，其中的值除了在t中出现过的那些字符是正数，其他位置都还是0。然后第一次移动完右边界开始准备移动左边界前，在子数组中有但是在t中没有的那些字符在typeGapMap中的值由0变成了负数的（说明盈余了），但是在子数组中有且在t有的那些字符在typeGapMap中的值变成了0或负数（说明这些字符都不缺了，甚至还有盈余）。即此时typeGapMap中的值要么是负数，要么是0，没有正数了（如果有正数说明还缺）。因此后续移动左边界前可以通过判左端点那个位置的字符在typeGapMap中的值来判断这个左端点的字符（即将要从左边界移出去的那个元素）是否是用来覆盖t的必要元素且它的个数是否足够用来覆盖t。如果左端点这个字符的值是负数，说明不缺，直接将其移出去就好了。但是如果这个值刚好是0，那就说明如果移出这个字符，就会刚好缺一个字符来覆盖t，因此需要将缺的字符种类数从0变成1（也就是说此时缺一种字符就可以将t覆盖），然后接着再去移动右边界，进入下一轮移动循环。

```java
class Solution {
    public String minWindow(String s, String t) {
        // 1. 【需求统计】：统计 t 中每个字符的需求数量
        int[] needCharCount = new int[128];
        for (char c : t.toCharArray()) {
            needCharCount[c]++;
        }

        // 统计 t 中一共有多少种“必须凑齐”的字符类型
        int needTypeCount = 0;
        for (int i = 0; i < 128; i++) {
            if (needCharCount[i] > 0) {
                needTypeCount++;
            }
        }

        // 2. 【状态初始化】：定义窗口变量
        int left = 0;
        int right = 0;
        int windowValidTypeCount = 0; // 窗口内已经达标（数量满足需求）的字符种类数
        int[] windowCharCount = new int[128]; // 只记录窗口内“有效零件”的数量，而不是窗口内所有字符的数量

        // 记录结果：最短子串的起始索引和长度
        int start = 0;
        int minLen = Integer.MAX_VALUE;

        // 3. 【滑动窗口逻辑】
        while (right < s.length()) {
            // --- A. 窗口扩大阶段 ---
            char joinChar = s.charAt(right);
            right++; // 右边界向右移

            // 如果新加入的字符是 t 中需要的
            if (needCharCount[joinChar] > 0) {
		            // 正式加入窗口
                windowCharCount[joinChar]++;
                // 当这个字符在窗口里的数量“刚好”等于需求数量时，该类零件凑齐了
                if (windowCharCount[joinChar] == needCharCount[joinChar]) {
                    windowValidTypeCount++;
                }
            }

            // --- B. 窗口收缩阶段 ---
            // 只要当前窗口已经涵盖了所有需要的字符，就尝试收缩左边界来寻找“最小”子串
            while (windowValidTypeCount == needTypeCount) {
                // 更新最短长度记录
                if (right - left < minLen) {
                    start = left;
                    minLen = right - left;
                }

                // 准备移出左边的字符
                char exitChar = s.charAt(left);
                left++; // 左边界向右移

                // 如果移出的字符是 t 中需要的
                if (needCharCount[exitChar] > 0) {
                    // 如果移出前数量刚好等于需求量，移出后就不达标了，valid 计数减 1
                    if (windowCharCount[exitChar] == needCharCount[exitChar]) {
                        windowValidTypeCount--;
                    }
                    // 正式移出窗口
                    windowCharCount[exitChar]--;
                }
            }
        }

        // 4. 【输出结果】：如果 minLen 没被更新过，说明没找到，返回空串
        return minLen == Integer.MAX_VALUE ? "" : s.substring(start, start + minLen);
    }
}
```
