# 39. 组合总和

[https://leetcode.cn/problems/combination-sum/description/](https://leetcode.cn/problems/combination-sum/description/)

本题与[**77. 组合**](77%20%E7%BB%84%E5%90%88%201c842abd57ae80ecb30fd195a310ddd7.md) 和[**216. 组合总和 III**](216%20%E7%BB%84%E5%90%88%E6%80%BB%E5%92%8C%20III%201ca42abd57ae8053b06ff71f49c18889.md) 这两题差不多，唯一的区别就是本题的箱子可以是无限个，直到箱子里面的数的总和超过某个值为止，就不再继续递归选择下一个箱子。

本题还需要一个index来控制每个箱子选择数字的起始位置，为什么？因为题目说组合不可以相同。假设`candidates = [2,3,6,7]`，如果第一个箱子选择了2，第二个箱子选择了3，当后续箱子都递归完之后，第一个箱子选择3，这时候第二个箱子就不应该从头开始选择数字，也就是不应该从2开始选，不然与”第一个箱子选择2，第二个箱子选择3“出现重复，这时第二个箱子应该从3开始选（为什么不是从6开始选呢？因为本题说每个数字可以**无限制重复被选取**）。

总结：如果是一个集合中求组合的话，就需要`index`，比如[**77. 组合**](77%20%E7%BB%84%E5%90%88%201c842abd57ae80ecb30fd195a310ddd7.md) 和[**216. 组合总和 III**](216%20%E7%BB%84%E5%90%88%E6%80%BB%E5%92%8C%20III%201ca42abd57ae8053b06ff71f49c18889.md) ；如果是多个集合间取组合，各个集合之间相互不影响，那么就不用`index`，比如[**17. 电话号码的字母组合**](17%20%E7%94%B5%E8%AF%9D%E5%8F%B7%E7%A0%81%E7%9A%84%E5%AD%97%E6%AF%8D%E7%BB%84%E5%90%88%201cb42abd57ae80ea863edbfd4b56a2e0.md) 。代码如下：

```java
// 方法一：非剪枝优化版本
class Solution {
    public List<List<Integer>> combinationSum(int[] candidates, int target) {
        List<List<Integer>> res = new ArrayList<>();
        List<Integer> path = new ArrayList<>();
        int sum = 0;
        backtrack(candidates, target, sum, path, res, 0);
        return res;
    }

    public void backtrack(int[] candidates, int target, int sum, 
												  List<Integer> path, List<List<Integer>> res, int begin) {
        if(sum >= target){
            if(sum == target){
                res.add(new ArrayList<>(path));
            }
            return;
        }
        
        for(int i = begin; i < candidates.length; i++){
            sum += candidates[i];
            path.add(candidates[i]);
            backtrack(candidates, target, sum, path, res, i);
            path.remove(path.size() - 1);
            sum -= candidates[i];
        }
    }
}

// 方法二：剪枝优化版本
class Solution {
    public List<List<Integer>> combinationSum(int[] candidates, int target) {
        List<List<Integer>> res = new ArrayList<>();
        List<Integer> path = new ArrayList<>();
        // 关键点 1: 先排序，为剪枝做准备
        Arrays.sort(candidates);
        backtrack(candidates, target, path, res, 0);
        return res;
    }

    public void backtrack(int[] candidates, int target, 
											    List<Integer> path, List<List<Integer>> res, int begin) {
        // 结束条件：刚好凑齐
        if (target == 0) {
            res.add(new ArrayList<>(path));
            return;
        }
        
        // 错误的剪枝
        // if(target < 0){
        //     return;
        // }

        for (int i = begin; i < candidates.length; i++) {
            // 关键点 2: 剪枝优化（正确的剪枝）
            // 如果当前数字已经大于剩余需要的 target，直接退出循环（不再看后面的数字）
            if (target - candidates[i] < 0) {
                break;
            }

            path.add(candidates[i]);
            // 关键点 3: 直接传 target - candidates[i]，省去了 sum 变量的回退操作
            backtrack(candidates, target - candidates[i], path, res, i);
            path.remove(path.size() - 1);
        }
    }
}
```

注意：我之前的剪枝操作其实作用不是很大，这样的剪枝操作只是对某一个箱子的某一个数字进行剪枝，但是还是会对上个箱子的下一个数字进行递归，而这个数字是没必要继续递归的，因为这个数字比刚刚被剪枝那个数字还要大。正确的剪枝操作会直接退出整个`for`循环，当前箱子的后续每个数字都没有必要再遍历了。
